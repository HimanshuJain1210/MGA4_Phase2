How Might We…
Four barriers from Phase 1 research → opportunity spaces → solution directions

Decomposition Wall

P3
HMW give people a template to map their own recurring tasks as trigger → step → output, before touching any tool?
HMW make "what should I automate?" answerable in under 10 minutes?
HMW show users the right tool tier after they describe their task — not before?
Wild idea: An AI that watches your work for a week and auto-surfaces automation candidates from your calendar and inbox.
→ WorkflowFirst

Peer Proof Gap

P2
HMW replace YouTube tutorials with a 10-min recording from someone in the exact same role?
HMW match users to a peer — same title, same org-type — who has already crossed?
HMW let users search for proof by role, not by industry?
Wild idea: Pay a peer in your exact role $30 for a structured 20-minute live activation session.
→ ProofMatch

First-Ship Wall

P3
HMW give a stranded PM a real shipped automation in their actual job — within 7 days?
HMW combine learning + portfolio proof so every build becomes a career asset?
HMW reduce the Lovable-to-production wall for non-technical PMs?
Wild idea: A "fluency passport" — a portable, employer-readable proof-of-capability document tied to a real shipped output.
→ ShipSprint

Trigger Absence

P2 / Low
HMW surface activation moments (job hunt, performance review, peer crossing) and meet users exactly then?
HMW create urgency without leaning on fear — which generates content consumption, not building?
HMW design a product that waits for the trigger moment rather than trying to create it?
Not prioritised for Phase 3: high reach, low conversion signal. No acute trigger = no purchase behavior.
→ Not now

Why WorkflowFirst ranks #1

It solves the upstream blocker all three barriers share. If users can't decompose their work, ProofMatch and ShipSprint both fail too. WorkflowFirst is the wedge — the pre-step that every existing tool (Zapier, n8n, Lovable, ADPList) has skipped.

Top 3 Concept Briefs
Each concept breaks exactly one specific mechanism failure identified in Phase 1
Concept #1 · Wedge Product

WorkflowFirst

A guided canvas that takes a non-technical professional from "I want to automate something" to a concrete trigger → steps → output spec — before recommending any tool or writing any code.

Barrier it breaks
Decomposition Wall — users stall before tools because they can't describe what they want with enough specificity to make a tool choice.
Key features
  • Role-prefilled templates (PM, Ops, Marketing, CS)
  • Decomposition coach — AI asks "what triggers this? what comes next?" not concepts
  • Complexity scorer → recommends ChatGPT / Zapier / n8n / code
  • Portable one-page automation spec output
What it is NOT
Not a tool-building platform. It is the pre-step that Zapier, n8n, and Lovable have all skipped.
Differentiation
Section AI teaches concepts. ADPList connects people. n8n builds workflows. No product helps users describe their own work in buildable terms. This is structurally absent.
Segment: P3 Aspiring Builders + P2 Surface Users
Concept #2 · Activation Layer

ProofMatch

A searchable library of 10-minute proof recordings — real professionals showing one real AI workflow from their actual job — matched by exact role and org-type, not industry.

Barrier it breaks
Peer Proof Gap — cross-role demos inspire but don't activate. Rohan watched his best engineer demo AI twice. Usage at his desk: unchanged.
Key features
  • Role + org-type matching (not industry — Rohan's finding)
  • Fixed format: task · trigger · what AI does · real ROI · setup time
  • "Try this" → pre-loads WorkflowFirst canvas with automation structure
  • Contributor program: P4 practitioners submit recordings for visibility
  • Optional 20-min live session with recording author
What it is NOT
Not a course. Not a mentoring marketplace. Not YouTube. It is structured role-matched proof, not instruction.
Competitive gap
ADPList has 30K mentors but unstructured sessions. YouTube demos aren't role-matched. The 10-min fixed-format + role matching is the structural moat.
Segment: P2 Surbhi/Rohan profiles
Concept #3 · Premium Layer

ShipSprint

A 7-day structured sprint from "stuck" to "shipped and portfolio-documented" — in your actual job, on a real automation, with a peer guide who has crossed the same wall.

Barrier it breaks
First-Ship Wall — motivated, capable professionals can prototype. They cannot ship. The gap is not motivation — it's structured accountability + a portfolio output that makes the effort count.
7-day structure
  • Day 1-2: Decompose + specify (WorkflowFirst canvas)
  • Day 3-5: Build + test with async peer guide available
  • Day 6-7: Ship + document portfolio case study
Key differentiators vs Will Lowrey PM OS
  • 7 days, not 4 weeks
  • No curriculum — output is the product, not learning
  • 1:1 role-matched peer, not cohort
  • Portfolio artifact = portable proof of AI fluency
Phase 3 gate
Show a stranded PM Will Lowrey's landing page. If they can't say why ShipSprint is different, differentiation must sharpen before building.
Segment: P3 Capable Stranded PMs

The integrated motion — one product, three layers

These are not three separate products. Each layer feeds the next. A user sees proof in ProofMatch → maps their version in WorkflowFirst → ships with accountability in ShipSprint.

ProofMatch activates → WorkflowFirst specifies → ShipSprint ships

Open Questions for Phase 3
What we don't yet know — and what must be resolved before building
Critical

Live vs. recorded peer demo — which activates?

If a recorded demo from a role-proximate peer activates equally to a live session, the product scales as a platform. If live presence is required, it is a service first. Business model changes completely. Highest-stakes open question before any build.

Critical

Does WorkflowFirst work self-serve, or does it need a live AI coach?

Determines whether Phase 3 build is a guided canvas (lower complexity) or a conversational AI agent (higher complexity, higher moat). Must be tested with 3+ stuck professionals in a prototype session.

High

ShipSprint vs Will Lowrey's PM OS — does differentiation hold?

Show a stranded PM Will Lowrey's landing page and ask "why would you not just do this?" If the answer is unsatisfying, the segment or the 20% differentiation must change. Non-negotiable gate before building ShipSprint.

High

Portfolio motive — core feature or nice-to-have?

Ritvik is explicit: building to solve a problem AND prove capability simultaneously. If this dual motive is widespread, the portfolio artifact is a core feature. Ask every Phase 3 recruit: "If you shipped a working automation this week, what would you do with it?"

High

What is the minimum viable "first win"?

Chandu's 7hr → 1hr moment was dramatic. Is that the bar, or can a 30-minute save trigger the same identity shift? Determines the design bar for the week-one WorkflowFirst experience.

Medium

Finance as a separate ICP?

One data point in Phase 1. The trust-first blocker in finance is structurally distinct — domain stakes (wrong numbers, data leaks) block every first attempt. If 3+ finance professionals from different orgs name the same barrier, it requires a distinct product track the current wedge cannot serve.

Medium

Does peer activation work outside tech-adjacent industries?

Every confirmed activation event in Phase 1 was in tech or tech-adjacent. Healthcare, legal, education are entirely absent. Phase 3 must recruit at least 3 interviews each from non-tech-adjacent verticals before claiming the mechanism generalises.
